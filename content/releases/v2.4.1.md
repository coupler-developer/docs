## 목적

- Android Google Play `2.4.0 (102)`와 iOS App Store `2.4.1 (102)`를 하나의 앱 버전으로 합치지 않고
  platform별 실제 상태로 고정한다.
- 이미 확정된 DB migration 전용 `v2.4.0` 기록·태그·GitHub Release를 수정하지 않는다.
- 확인할 수 없는 iOS archive/source를 추정 커밋이나 사후 태그로 꾸미지 않고 한계로 종결한다.

## 릴리스 결과

- Android는 제공된 Google Play Console 화면에서 최신 프로덕션 `102 (2.4.0)`, 출시율 `100%`,
  게시되지 않은 변경사항 없음으로 확인했다.
- iOS App Store는 출시 책임자가 `2.4.1 (102)`로 확인했다. 원본 archive와 exact source가 남지 않아
  iOS `v2.4.1` Mobile 태그는 만들지 않는다.
- Mobile `v2.4.0` 태그 target은 Android `2.4.0 (102)` source와 일치한다. 태그 설명에 포함된 iOS 완료와
  docs `v2.4.0` 기준 문구는 이 기록의 iOS source 증빙으로 사용하지 않으며 기존 태그 ref는 이동하지 않는다.
- Apple 공개 Lookup API는 2026-08-04 KST 조회에서 아직 `2.3.0 (101)`을 반환했다. 이를 근거로 출시 책임자의
  App Store Connect 확인을 다른 버전으로 덮어쓰거나 공개 전파 완료를 독립 확인했다고 주장하지 않는다.

## 메인 흐름

1. 기존 docs `v2.4.0`을 DB migration 전용 불변 기록으로 유지했다.
2. Mobile `v2.4.0` target에서 Android `2.4.0 (102)` metadata와 source commit을 확인했다.
3. iOS 실제 Store `2.4.1 (102)`와 Git source `2.4.0 (102)`의 불일치를 분리했다.
4. 로컬 archive, fetched/ref·reflog·unreachable commit에서 iOS `2.4.1` source를 탐색했으나 찾지 못했다.
5. Android는 `verified`, iOS는 `unavailable-historical`로 기록하고 iOS tag·commit을 비워 두었다.
6. platform별 매핑과 한계를 신규 docs `v2.4.1` 최종 기록으로 고정했다.

## 롤백 기준

- Android 문제는 Google Play rollout 중단 또는 더 높은 build의 hotfix 제출로 처리한다.
- iOS 문제는 App Store release 제어 또는 더 높은 build의 hotfix 제출로 처리한다.
- iOS `2.4.1 (102)`의 source rollback 기준점은 복구되지 않았으므로 기존 Mobile 태그를 임의로 대용하지 않는다.
- DB, API, Admin, NextPush와 기존 `v2.4.0` 기록·태그는 이번 롤백 범위가 아니다.
