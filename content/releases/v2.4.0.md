## 릴리스 결과

- DB migration: 2026-08-04 KST 운영계에 98·99를 적용했다. `schema_migrations`에는 migration 98
  checksum `37b81efdf3e5154def46d891cd56b9ae6f0f1686f0f554480164e14100b7f57f`와 migration 99 checksum
  `3f1b9bd74c6a6d95804bb73643916d883c1c24832dead8ee0792fb8d72c405ab`가 기록됐고 pending은 0건이다.
  `t_match.lounge_id`와 `idx_t_match_lounge_id`, `t_setting.id=26, value=-5` postcondition을 확인했다.
  긴급 적용 전에 canonical dev/prod plan·execution artifact를 만들지 못한 사실은 그대로 보존하고 사후
  제조하지 않았다. 2026-08-04 KST read-only 재검증에서 API `v2.4.0` catalog 26/26 resolved, pending·gap
  0건, 운영 identity·schema fingerprint, 98·99 ledger/checksum과 live postcondition을 다시 확인해
  canonical chain이 없음을 숨기지 않는 위반 기록으로 DB scope를 닫았다. Apple 계정·결제 복구는 98·99와 분리된 선택 운영
  작업이다.
- contracts package: source와 API/Admin/Mobile은 stable `0.1.27`에 정렬돼 있다. 최종 API ref에서 source tree
  동일성과 publish workflow를 다시 고정한다.
- API: `299abc63d0c4cebaaff9f27a9f1484e0ef82c9db` 운영 배포, PM2 `online`, 외부 HTTP 200을 확인하고
  annotated `v2.4.0` 태그를 생성했다. terminal 계약·복구 증빙은 계속 정리한다.
- Admin: `6a1ca088b8ea7b7498c047cd8d035ae620a45b4c` 정적 artifact 운영 배포 뒤 nginx 설정 검사와 내부·외부
  HTTP 200을 확인하고 annotated `v2.4.0` 태그를 생성했다. terminal rollback 증빙은 계속 정리한다.
- Mobile Store: Android/iOS version을 `2.4.0 (102)`로 맞춘 로컬 릴리스 후보를 준비했다. Store에서 build
  `102`가 미사용인지 확인하기 전에는 제출하지 않는다.
- Mobile NextPush: Android/iOS Production target binary를 `2.4.0`으로 맞춘 로컬 릴리스 후보를 준비했다.
  Store artifact 고정 전에는 업로드하지 않는다.
- docs: 운영 DB와 API·Admin 배포 결과 및 API·Admin 태그를 반영했다. Mobile 출시 증빙과 최종 docs
  `v2.4.0` 태그는 아직 생성하지 않았다.

## 롤백 기준

- DB: 2026-08-04 backup과 적용 ledger를 보존한다. rollback이 필요하면 임의 역쿼리 대신 실제 변경 영향과
  backup을 확인한 승인 절차를 따른다.
- API: 현재 운영 tag를 기준으로 복구하되 persisted state·queue·외부효과 안전 근거와 이전 소비자 rollback
  case가 없으면 이전 binary로 내리지 않는다.
- Admin: 현재 운영 artifact를 rollback 기준으로 보존하고 API와 독립적으로 정적 artifact를 복원한다.
- Mobile Store: 승인 전 제출을 중단하고, 출시 뒤에는 기존 Store binary를 직접 rollback할 수 없으므로 API
  하위 호환과 NextPush 비활성화로 복구한다.
- Mobile NextPush: 새 label을 비활성화하고 직전 Production label cohort로 복구한다.
