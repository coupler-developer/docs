## 롤백 기준

- artifact 준비: version, 서명, 운영 endpoint 또는 digest 검증이 실패하면 Store에 제출하지 않고 원인을 수정한 새 build로 다시 준비한다.
- DB/API: migration guard나 drain이 실패하면 API를 시작하지 않는다. 적용 뒤에는 스키마를 되돌리거나 직전 API를 추정 배포하지 않고 고정 source 기반 forward fix를 사용한다.
- Admin: API 운영 smoke 전에는 배포하지 않는다. 배포 후 실패하면 봉인한 직전 정적 artifact로 복원한다.
- Store 제출 전: 제출 책임자가 exact source, platform version/build와 검증된 artifact를 대조하지 못하면 제출하지 않는다.
- Store 제출 후 공개 전: Store Console에서 제출·출시 진행을 중단하고 이미 사용한 build number를 재사용하지 않는다.
- Store 공개 후: rollout 중단 또는 검증된 후속 build로 복구하며 NextPush rollback으로 Store binary 문제를 우회하지 않는다.
- docs: terminal 증빙이 갖춰지기 전에는 Draft PR을 병합하거나 `v2.5.4` tag를 생성하지 않는다.
